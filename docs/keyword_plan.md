- `scripts/kw_research.py --deep --resume` — 13개 사이트, 카드 있는 종류 390개 전부. 힌트 = 종류 이름 + 카드의 모든 조건·방식·브랜드(5개씩) → 네이버 검색광고 키워드도구.

## 4. 작성 순서 (검색수 큰 것부터)
| 차수 | 대상 | 예상 페이지 | 방법 |
|---|---|---|---|
| 1차 | 월 1,000+ 1,719개 | 검색어 페이지 약 1,400 + 질문 글 약 120 | `search_input.py` → `prompts/search.md`(같은 뜻은 하나만, 상품과 안 맞으면 뺌) → cards-load --check |
| 2차 | 월 100~999 3,440개 | 약 2,800 + 질문 글 약 450 | 같은 방법 |
| 3차 | 월 10~99 3,848개 | 약 3,000 + 질문 글 약 900 | 같은 방법 |
- 차수마다: 에이전트가 종류 묶음으로 작성 → `ray_check --files`(같은 문장 30%·본문 1,800자) → 커밋 → 서버 `jobs refresh` → 매일 300쪽 공개.
- 브랜드 키워드(스탠리·삼성 노트북 등)는 그 브랜드 상품이 실제로 있을 때만, 사실 표기로(공식·제휴 암시 금지 — CLAUDE.md 규칙).

## 5. '상품 없음' 후보 처리
- 쿠팡 사이트: 월 1,000+ 후보(5,350개 — 롱패딩·패딩조끼·발가락양말·12월 달력 등)를 수집 대기열(`coupang_kw`)에 검색어로 넣어 상품을 받으면 servable 로 바뀐다 → 다음 차수에 포함.
- 새 종류감(종류 이름과 다른 물건)은 `data/coupang_kinds.json` 확장 후보로 따로 뽑는다.
- 네이버 사이트: 상품 CSV 를 새로 받을 때 다시 판정.

## 6. 기존 페이지에 검색량 반영
- `keyword_combos.volume_total` 에 측정값을 넣고, 아직 안 연 페이지의 공개 순서(priority)를 검색량 순으로 → 매일 300쪽이 수요 큰 것부터 열린다.
- 매주: 새 종류·새 조건을 넣기 전에 "조건 + 종류" 검색수를 먼저 재서 검색되는 것만 카드에 쓴다. 조사 다시 돌리기(`--resume` 없이) → 후보 목록 갱신.

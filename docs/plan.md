## 0. 한 줄 요약

**키워드·페이지는 "상품 종류"(예: 미니 가습기)에 붙이고, 실제 상품 링크는 갈아 끼우는 부품으로 둔다.**

## 3. 상품 링크를 열어 봐야 하나? — 아니다

- 제휴 링크(`naver.me`)를 봇이나 우리가 열면 **클릭으로 집계**된다. 클릭은 많은데 구매가 없는 계정은 부정 트래픽으로 의심받을 수 있다.
- 스마트스토어 상품 페이지를 긁는 것은 네이버 약관 위험이 있고, 1,717개를 사람이 열어 보는 것도 의미가 적다.
- **필요한 정보는 CSV 에 있다**: 상품명(용량·방식·무선·USB·브랜드가 거의 다 들어 있음)·스토어·수수료·판매가·리뷰 수.
- 본문은 개별 상품 스펙이 아니라 **종류 단위 정보**(고르는 기준·방식 차이·관리법)라서 상품 상세가 필요 없다.
- 가격은 매일 바뀌므로 **페이지에 적지 않는다**("가격·할인은 판매처에서 확인"). 오래된 가격 표시는 표시광고법 위험.
- 상품 이미지도 쓰지 않는다(저작권). 종류별 대표 사진(무료 라이선스) 또는 글자 카드.
- 예외: 사용자가 원하면 상위 수수료 상품 20~30개만 사용자가 직접 열어 옵션명을 메모 → CSV 에 열 추가.

## 4. 구조

```
상품군 (서브도메인)        heat · air · clean · kitchen · beauty · digital · life
 └ 상품 종류 (약 200)      미니 가습기, 가열식 가습기, 탄소매트, 오방난로, 무선 청소기 …   ← 키워드의 주인
     ├ 키워드 페이지        종류 × 수식어 조합, 종류마다 1,000~3,000개                     ← 바뀌지 않는 자산
     └ 상품 슬롯            그 종류·특징에 맞는 현재 상품 3~6개                              ← 갈아 끼우는 부품
```

- 서브도메인 예: `heat.golrabom.kr`, `air.golrabom.kr` … (상품군 하나가 나빠져도 다른 곳에 덜 번짐)
- 주소: `/{종류}/` (허브), `/{종류}/{수식어1}-{수식어2}/` (키워드), `/{종류}/qna/{슬러그}/` (질문 글). 한글 슬러그, 끝 슬래시, 소문자.
- 페이지가 상품을 고르는 규칙: (1) 같은 종류 (2) 페이지 수식어의 '특징' 태그와 일치(예: '대용량' 페이지 → 대용량 태그 상품) (3) 점수 순 (수수료율 × 판매가 × log 리뷰 수, 오픈 후엔 실제 클릭·판매 실적) (4) 페이지마다 시드로 순서를 조금씩 다르게 (5) 해당 상품이 없으면 같은 상품군 비슷한 종류에서 채움 → 빈 페이지 없음.

### F2. 상품 적재 (Claude, 반나절)
- CSV 파서: 한 셀에 여러 줄이 든 형식. `수수료 N%`, `NEW`, `추가 N%`(가산 수수료), 판매가·할인율·할인가, 상품명, 스토어, 평점, `리뷰 N` 을 뽑는다. 두 형식(줄바꿈형·한 줄형)이 섞여 있다.
- offers 행: advertiser=스토어, name=상품명, url=제휴 링크(고유키), fee=수수료(+추가), list_price, review_count, rating, imported_at, status(active/inactive).
- 분류: ① 사전 매칭(종류어 사전, 85% 처리) ② 나머지 263개는 Claude 가 이름을 읽고 종류·특징 태그를 JSON 으로 채움 ③ 특징 태그 추출(용량 1L/3L/대용량, 가열식/초음파/복합식, 무선/USB/충전, 미니/소형, 무소음 표기 등 — 상품명에 있는 것만).
- **교체 기능(중요)**: 관리자 > 상품 CSV 업로드 → URL 로 대조 → 새 상품 추가·자동 분류 / 빠진 상품 inactive / 수수료 변경 반영 → 결과 표(추가 N · 제외 N · 변경 N). 페이지 본문은 건드리지 않는다. 상품 하나 링크만 바꾸는 편집 화면도.

### F3. 종류·키워드 (Claude, 1일)
- 종류 목록 확정: 기본 60개를 방식·크기로 쪼개 약 200개(예: 가습기 → 미니·가열식·초음파·복합식·대용량·아기·사무실용). 종류마다 상품이 3개 이상 있어야 독립 종류로 둔다.
- 수식어 사전(종류군별): 공간(원룸·사무실 책상·침실·아기방·거실·차량·캠핑·기숙사) / 대상(신생아·자취생·수험생·부모님 선물·비염) / 상황(겨울·환절기·잘 때·에어컨 켤 때) / 특징(무소음·USB·무선·대용량·세척 쉬운·가열식·무드등) / 가격대(2만 원대·3만 원 이하·5만 원대) / 의도(추천·고르는 법·비교·장단점) / 질문(세척 방법·전기세·수돗물·하얀 가루·곰팡이).
- **브랜드 축**(사용자 제안 2026-11-19): CSV 에 상품이 3개 이상인 브랜드(브라운·필립스·블라우풍트·테팔·쿠쿠·한경희·앤커·샤크닌자·소닉케어 … 상품명·스토어명에서 추출)만 수식어로 쓴다.
  예: "브라운 전기면도기 고르는 법", "필립스 vs 브라운 면도기 차이", "테팔 에어프라이어 용량". 허브·롱테일 본문에는 "대표 브랜드로 A·B·C 가 있다"를 **상품 수 순 또는 가나다순**으로(순위처럼 보이지 않게) 넣는다.
  브랜드 상품이 목록에서 모두 빠지면 그 페이지의 상품 슬롯은 같은 종류의 다른 상품으로 채우고, 본문의 브랜드 설명은 상품명 기반 사실만 썼으므로 그대로 둔다.
- 조합: 종류 × 수식어 1개 + 2개 조합(서로 어울리는 축끼리만: 공간×특징, 대상×특징, 공간×가격대 …). 뜻이 같은 조합(원룸·자취방)은 대표 하나로 묶고 나머지는 301.
- 등급: A(종류 단독·종류×의도·종류×대표 공간), B(수식어 1개), C(수식어 2개), D(3개·질문 변형). 우선순위 점수 = 등급 + 계절(데이터랩) + 수수료 수준.
- 규모 목표: 약 20만~50만 키워드(종류당 1,000~3,000). 실제 수는 F3 끝에 표로 보고하고 사용자 확인.
- 사이트 행: 상품군 7개 = sites 7행, 종류 = verticals(또는 topics). cpa_prj 의 키워드 풀 생성기(keywords/build_pool.py) 방식 재사용.

### F4. 콘텐츠 — Claude Code 로 쓰는 것과 조립하는 것 (2~3일)
1. **종류 사실 카드** (약 200편, Claude 작성): 고르는 기준 6~10개(항목 | 확인할 것 | 달라지는 이유), 방식별 장단점, 공간별·대상별 달라지는 점(수식어마다 2~3문장), 관리·세척, 자주 하는 실수, 전기·소음 등 확인 포인트(수치는 근거 있는 것만), 질문과 답 풀 12~20개, 첫 문장 후보 6벌, 후킹 제목 틀 6벌. JSON 으로 `content/cards/<종류>.json` → 금지 표현 린트 → 승인.
2. **허브** (종류 200 + 상품군 7, Claude 작성): 1,500~2,500자.
3. **질문 글** (Claude 작성, 하루 30~50편 분량을 세션에서 꾸준히): 종류별 질문형 롱테일. cpa_prj 의 질문 글 경로(posts-seed → content/queue/*.prompt.md → 세션이 *.json 작성 → submit-dir → 점검 → 승인 → 하루 N편 공개) 그대로.
4. **키워드 롱테일 (조립)**: 사실 카드에서 그 페이지 수식어에 맞는 블록을 골라 넣는다 — 첫 문장(6벌 중 시드), 수식어별 문단, 기준표 3~5행(시드로 부분집합), 질문 3개(부분집합), 상품 카드 3~6개, 관련 키워드 링크. cpa_prj 지역 페이지에서 같은 문장 30% 이하를 맞춘 방식.
- 쓰는 방법(구독 세션): `jobs export-prompts --type card|hub|post --limit 20` → 세션이 `content/queue/*.json` 을 쓴다(서브에이전트 여러 개로 병렬 가능 — 사용자가 "워크플로로" 라고 하면 Workflow 사용) → `jobs submit-dir` 가 채점·승인.

### F5. 페이지 틀과 문구 (1일)
- 디자인: 흰 바탕 블로그형, 핵심 답이 위, 상품 카드는 본문 중간과 아래, 짙은 덩어리·세로 무늬·숫자 띠·사진 캡션 금지(사용자 규칙). 모바일 390px 확인.
- 순서: 제목 → **고지 한 줄**("이 글에는 네이버 쇼핑 제휴 링크가 있으며, 구매 시 수수료를 받을 수 있습니다") → 바로 답(첫 문장) → 핵심 요약 → 목차 → 고르는 기준 표 → **상품 카드** → 수식어 설명 → 비교·장단점 → 질문 → 관련 키워드 → 아래 고지.
- 상품 카드: '광고' 표시 · 상품명 · 스토어 · 이 페이지 조건과 맞는 이유 한 줄(특징 태그에서) · 버튼 "할인가 확인하기"/"오늘 가격 보기". 가격·평점 숫자는 쓰지 않는다. 링크는 `/go/<id>` 경유, `rel="sponsored nofollow noopener" target=_blank`. 클릭 로그로 상품·페이지 실적 집계.
- 후킹 제목 예: "원룸 미니 가습기, 소음 때문에 버리기 전에 볼 3가지" / "아기방 가습기 고를 때 세척부터 보는 이유" / "사무실 USB 가습기, 3만 원 이하에서 고르는 기준". 금지: 1위·최저가·최고·품절 임박·"직접 써 보니"(지어낸 후기)·근거 없는 퍼센트.
- 브랜드명: 제목·본문·소제목에 써도 된다(상품을 설명하려는 사실 표기). 단 "공식·정품 인증·브랜드 제휴"처럼 브랜드와 관계가 있는 것처럼 쓰지 않는다, 로고 금지, 브랜드끼리 우열을 단정하거나 깎아내리지 않는다(표시광고법 비방), 브랜드 제품 스펙은 상품명에 있는 것만. 브랜드를 도메인·사이트 이름에 넣지 않는다.
- 구조화 데이터: Article(질문 글)·FAQPage·BreadcrumbList·ItemList(내부 관련 페이지). **Product 스키마는 쓰지 않는다**(가격·리뷰를 우리가 보증할 수 없음).
- OG 이미지: 종류별 카드(배치 생성).

### F6. 점검 (반나절)
- site-launch 스킬 `check_all.py` (snapshot_sites.py 로 사이트별 60쪽): SEO 구조·같은 문장 30% 이하·첫 문장 틀 50% 이하·AI 티·답 페이지 틀.
- 상품 슬롯이 빈 페이지 0, 끊긴 링크 0, 고지 문구 누락 0, 금지 표현 0.

### F7. 배포 (1시간, 사용자 붙여넣기 1줄)
- cpa_prj 의 `deploy/install.sh` 를 복사해 서브도메인 목록·DB 이름·포트만 바꾼다. DB 덤프를 저장소에 포함(비공개 저장소 권장).
- 서버: `bash <(curl -fsSL https://raw.githubusercontent.com/<저장소>/main/deploy/install.sh) golrabom.kr <메일>` → 패키지·코드·DB·서비스·DNS 확인·HTTPS·첫 오픈·cron·점검.
- cron: cpa_prj 와 겹치지 않게 05:40 (web_jd8 빌드 03:00, cpa_prj 05:10).

### F8. 순차 오픈
- D0: 상품군 허브 7 + 종류 허브 200 + 겨울 상품군(heat·air) A등급.
- 이후 매일: 우선순위 순으로 하루 몇천 쪽(사용자가 숫자 결정 — cpa_prj 처럼 `plan --days --rest-days --then`), 질문 글 하루 30~50편.
- 검색 등록: 네이버 서치어드바이저 서브도메인 7개 각각 + 구글 서치콘솔 도메인 속성 1개, sitemap 제출. SEO 대시보드 연결.

### F9. 운영
- 매주: 네이버 커넥트에서 최신 상품 목록 CSV 내려받아 관리자에 업로드 → 단종 상품 자동 제외·새 상품 자동 배치.
- 매주: `/go/` 클릭 집계 × 커넥트 정산 내역 대조 → 상품·종류별 수익표 → 점수 반영(잘 팔리는 상품 위로).
- 계절 교체: 봄(공기청정기·제습), 여름(선풍기·서큘레이터·모기퇴치), 가을(가습·전기매트), 겨울(난방). 계절 상품군 페이지를 먼저 연다.
- 질문 글은 세션에서 꾸준히 추가.

## 6. 오픈 전략 — 첫날 최대, 그 뒤 계속 확장 (사용자 결정 2026-11-19)

사용자 확정: 도메인 golrabom.kr, 외부 사이트 게시 OK(사용자 확인), 서브도메인 7개, **첫날 최대한 많이 열고 이후 계속 만든다.**
공개 수는 사용자가 정하는 값이다 — 줄이자고 하지 않는다(seo-monitor 전제). 위험은 대시보드 숫자로만 보고한다.

### 6-1. 첫날(D0) — 준비된 것 전부
- 첫날 오픈 전까지 **사실 카드가 승인된 종류 전부**의 페이지를 만든다: 상품군 허브 7 + 종류 허브 약 200 + 그 종류의 A·B·C 등급 키워드 페이지 전부 + 그때까지 쓴 질문 글 전부.
- 품질 게이트를 통과한 페이지는 D0 에 모두 공개(`plan` 첫날 몫 = 통과 전체). 통과 못 한 것만 다음 날 재시도.
- 목표 규모(추정): 종류 200 × A~C 평균 약 300 = **약 6만 쪽 + 허브·질문 글**. D 등급(깊은 롱테일)은 6-2 에서 매일 연다.
- D0 에 함께: 사이트맵(상품군별·묶음 1,000개 단위) · IndexNow 전량 전송(하루 1만 한도 → 이틀에 나눠 자동) · 서치어드바이저 7개·서치콘솔 도메인 등록 · 허브·상품군 페이지 수집 요청(하루 50) · 대시보드 연결.

### 6-2. 이후 매일 자동 공개
- D 등급 키워드: 사용자가 정한 하루 수(`plan --then N`)만큼 우선순위 순으로 — 계절 상품군 먼저(지금은 heat·air), 수수료 높은 종류 먼저.
- 질문 글: 세션에서 쓴 만큼 하루 N편(`posts_per_day`).
- 열린 페이지는 닫지 않는다. 새로 만든 페이지는 **기존 대기열 뒤에** 붙는다(우선순위 점수 + 생성 순서) → 확장해도 이미 열린 페이지·일정이 흔들리지 않는다.

### 6-3. 계속 만들기 — 확장 루틴 (매주 반복)
| 주기 | 할 일 | 결과 |
|---|---|---|
| 매일 | 세션에서 질문 글 30~50편 작성 → submit-dir → 자동 승인 → 다음 날부터 공개 | 글 계속 증가(RSS 로 빠른 수집) |
| 매주 | 커넥트 최신 CSV 업로드 → 단종 제외·신상품 자동 배치, **새 종류가 생기면** 사실 카드 작성 → 그 종류 키워드 페이지 생성 → 대기열 뒤에 추가 | 상품 교체 + 종류 확장 |
| 매주 | 수식어 사전 추가(새 공간·대상·상황·브랜드) → 기존 종류에 새 조합 키워드 생성 → 대기열 추가 | 키워드 확장 |
| 매주 | 클릭(`/go/`)·정산 대조 → 잘 팔리는 종류의 사실 카드 보강(질문 풀·비교 항목 추가) → 그 종류 페이지 본문이 풍부해짐 | 수익 페이지 강화 |
| 매월 | 데이터랩으로 다음 계절 수요 확인 → 다음 계절 상품군 우선순위 올림(봄: 공기청정기·제습 / 여름: 선풍기·모기 / 가을: 가습·전기매트) | 계절 선점 |
| 매월 | 대시보드: 상품군별 수집률·유입·클릭·판매 → 유입 없는 축은 확장 중단, 잘 되는 축은 수식어 추가 | 방향 조정 |

- 페이지를 늘려도 기존 페이지 본문이 크게 바뀌지 않게 한다: 카드 보강은 질문·비교 '추가'만, 기존 문장 교체는 한 번에 몰아서(바뀐 쪽 수 보고).
- 확장할 때마다 출시 점검(같은 문장 30% 이하)을 새 페이지 표본으로 다시 잰다.

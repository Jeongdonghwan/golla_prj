# 카드 보강(cards_more) 작성 지시 — 쿠팡 사이트 종류

작업 폴더: c:\side_Prj\shopa_prj. 받은 slug 마다 `content/cards/<slug>.json`(이미 있는 사실 카드, **고치지 않는다**)을 읽고, 그 카드에 덧붙일 문장을 `content/cards_more/<slug>.json` 에 새로 쓴다(Write 도구).
목적: 키워드 페이지의 번호 절 문단이 짧아(평균 139자) 본문이 1,200자 안팎이다. 보강 문장이 붙어 문단 200~260자, 본문 1,800자 이상이 되게 한다.

형식(참고: content/cards_more/가습기.json 을 먼저 읽는다 — 문장은 베끼지 않는다):
```json
{
 "criteria": {"<카드 criteria 의 item 그대로>": "덧붙임 한 문장", ...카드의 criteria 전부},
 "methods":  {"<카드 methods 의 name 그대로>": "덧붙임 두 문장", ...전부},
 "care":     {"<카드 care 문장 글자 그대로>": "덧붙임 한 문장", ...전부},
 "mistakes": {"<카드 mistakes 문장 그대로>": "덧붙임 한 문장", ...전부},
 "checks":   {"<카드 checks 문장 그대로>": "덧붙임 한 문장", ...전부},
 "axes": {"space": ["문장", "문장", "문장"], "persona": [...], "situation": [...], "feature": [...], "price": [...], "brand": [...], "search": [...]}
}
```
- 키는 카드의 글자와 **한 글자도 다르지 않게**(키가 안 맞으면 그 덧붙임이 빠진다). 카드에 mods 가 비어 있는 축도 axes 에는 7개 축 모두 3문장씩 쓴다.
- criteria·care·mistakes·checks 덧붙임: 한 문장 60~90자. 원래 문장을 되풀이하지 말고 **어디서·어떻게 확인하는지, 무엇과 견주는지** 같은 다음 한 걸음을 쓴다.
- methods: 두 문장 합쳐 100~140자(그 방식을 고르는 상황 + 고를 때 더 볼 것).
- axes: 특정 항목 이름(원룸·겨울 등) 없이, 그 축(공간/쓰는 사람/상황/특징/가격대/브랜드/검색어)으로 고를 때 이 종류에서 무엇이 달라지는지. 문장마다 60~90자.
- 모든 문장에 **그 종류만의 낱말**(종류 이름·부품·재질·쓰임)이 들어가, 다른 종류 카드로 옮기면 말이 안 되게 쓴다. 카드끼리·카드 안에서 같은 문장 금지.
- 금지: 아라비아 숫자, 물음표, 브랜드명, 지어낸 경험(써 보니·후기·만족), 과장(최고·완벽·무조건·보장), 효능 단정(치료·개선·면역·다이어트 효과), '가전'·판매처 이름·'공식·정품'. 금지어 목록 lint/forbidden.txt. 말투는 "~요"(~예요/~해요/~보세요).
- 식품·건강식품·화장품·유아용품·반려동물 먹거리·보호대류는 "제품 표기 확인"과 형태 차이만(prompts/card_coupang.md 와 같은 원칙).

점검(통과할 때까지 고친다): `cd /c/side_Prj/shopa_prj && PYTHONIOENCODING=utf-8 .venv/Scripts/flask --app app jobs cards-load --check --only <slug>`
그리고 스스로 확인: 키가 카드와 정확히 같은지(파이썬으로 카드의 criteria item·methods name·care/mistakes/checks 문장 집합과 보강 키 집합을 비교), 문장 길이 범위, 숫자·물음표 없음.

다른 파일은 고치지 않는다. git·DB 적재(--check 없는 cards-load) 금지. 끝나면 slug 별 '통과/실패'만 한 줄씩 보고한다.
